# Patch mechanism inventory — how vllm-neuron hooks vLLM

The ways the fork already changes upstream vLLM behavior. A design that names a patch surface names one of these; the porter rules at the end say how to add one. Paths are relative to the vllm-neuron checkout. Line numbers move on every pin bump, so this file names functions, never lines: derive lines with grep at the current pin. Every section was verified at the 0.29 line (`release-0.29.0.1.2.0`, Neuron SDK 2.33), where the native torch.compile route is the default and the XLA route is on its deprecation path (last release 2.34). An item marked **XLA only** never runs on the native route.

## Entry points

`pyproject.toml` declares two entry points. `vllm.platform_plugins` `neuron = "vllm_neuron:register"`: vLLM imports `vllm_neuron` and calls `register()`, which returns `None` when no `/dev/neuron*` device exists and neither `VLLM_NEURON_CPU_MODE=1` nor `VLLM_NEURON_CPU_COMPILE=1` is set, otherwise applies the three registration-time patches (mechanism 3) and returns `vllm_neuron.vllm.platform.NeuronPlatform` (`VLLM_NEURON_BACKEND` picks the route, not the class). `vllm.general_plugins` `neuron = "vllm_neuron.vllm.patches:apply_patches"`: a live layer since 0.29, which vLLM runs in every process it spawns (API, engine core, workers); it applies the DP load-balancer patch (mechanism 2).

Importing `vllm_neuron` has side effects before `register()` runs, in every process that imports the package, spawn-mode workers included: `CUDA_VISIBLE_DEVICES` cleared; the `VLLM_NEURON_MEGA_*` kernel-flag seeds set before the first `nkilib` import; a `PROMETHEUS_MULTIPROC_DIR` default; `_init_backend()`; then the port-hold, pin-memory and accelerator-empty-cache patches (mechanism 5). `_init_backend()` is the route fork. Native route: import `libtorch_neuronx_lite` (it names the PrivateUse1 `neuron` device), register the `neuron_libtorch_graph_capture` dynamo backend, return. **XLA only** and CPU mode: `PJRT_DEVICE=CPU`, the `neuron_libtorch` dynamo backend, Lite's `overrides.neuron_collectives` and `xla_collectives` imports, `sys.modules["torch.neuron"]`, the `torch.accelerator.current_accelerator` wrapper, and the CPU-mode stream patches. A change placed in that branch never runs on the default route.

Gone since 0.24, do not design on them: the `torch_neuronx` import redirector and `VLLM_NEURON_LIBTORCH_NEURONX_LITE`; `vllm_neuron/overrides/` and its `torch.library.impl` registrations; the pydantic schema mutation `_register_neuron_all2all_backend`. The all2all seam is now a config read: `NeuronDeviceCommunicator` (`vllm_neuron/parallel/neuron_communicator.py`) reads `additional_config.neuron_config.all2all_backend` and overrides upstream's `use_all2all` decision, and `check_and_update_config` validates `all2all_backend == "neuron"` for the MoE data-parallel expert-parallel case.

## The eight mechanisms

1. **Platform hooks and config-slot injection (sanctioned, not a patch).** vLLM calls `NeuronPlatform` classmethods; the plugin fills upstream config slots with dotted class paths that vLLM imports itself, workers included. `check_and_update_config` sets `worker_cls` (only when `"auto"`), `scheduler_cls` (only when `None` or an upstream default; an explicit value is kept with a warning), and the connector module path for `NeuronNixlConnector` and `NeuronDecodeBenchConnector`. `pre_register_and_update` registers `SyntheticNeuronModel` under `VLLM_NEURON_SYNTHETIC_MODEL=1`; `get_attn_backend_cls` returns the Neuron attention backend; `apply_config_platform_defaults` and `update_block_size_for_backend` set defaults, and on the native route the optimization level defaults to O2 (the start-up line "Using default optimization level O2 on the Neuron native route"). KV connectors subclass upstream classes with no patching.
2. **General-plugin layer.** `vllm_neuron/vllm/patches/__init__.py::apply_patches()` applies `apply_dp_load_balancer_patch` (`dp_load_balancer_patch.py`: keeps internal data-parallel routing admissions consistent across API workers). Startup-critical patches go here because vLLM's general-plugin hook runs in spawned engine, API and worker processes. Idempotence: an `_applied` global in `dp_load_balancer_patch.py`. Comments in the `apply_patches()` body record why two sibling patches are applied elsewhere (mechanisms 6 and 7).
3. **Registration-time config patches** (`register()`): `_patch_dcp_config_validation` in `platform.py` wraps `vllm.config.model.ModelConfig.verify_with_parallel_config` so the upstream DCP assertion is bypassed for prefill-DCP; if `vllm.config.model` is not importable yet, a `sys.addaudithook` handler applies it on first import (the hook self-disables but cannot be removed); idempotence `_dcp_config_patched` plus a `_neuron_dcp_patched` marker. `_patch_llm_init_optimization_level` wraps `LLM.__init__` to record whether `optimization_level` was passed, so the native O2 default does not override a user's value. `patch_vllm_config_for_neuron` (`model_runner_v2_policy.py`) installs the `use_v2_model_runner` property on `VllmConfig`, audit-hook deferred under an import cycle; it also wraps `EngineCoreProc.run_engine_core` (`_patch_engine_core_entrypoint_for_neuron`) to cache the runner decision before the engine normalizes data-parallel state and to apply the shm reader spin patch there. The class patch does not survive a worker spawn, so `NeuronWorker.__init__` re-applies it before reading `use_v2_model_runner`.
4. **Termination-timeout patches.** `_patch_termination_timeouts` in `platform.py` replaces `vllm.v1.utils.shutdown` AND `vllm.v1.engine.utils.shutdown` (both bindings, because `weakref.finalize` captured the second) and `MultiprocExecutor._ensure_worker_termination`, widening the SIGTERM-to-SIGKILL windows so profiling can flush. Called from `check_and_update_config`, which also applies `apply_epd_shm_patch` (mechanism 8); a no-op while `VLLM_NEURON_WORKER_TERMINATION_TIMEOUT` is at its default of 5. Idempotence: class flag `_termination_timeout_patched`.
5. **Import-time torch patches** (`__init__.py`, after `_init_backend()`, each guarded by an `_applied` global): `port_hold_patch.py` rebinds `torch.distributed.init_process_group`: for loopback `tcp://` init, rank 0 binds the port at once (or a fresh one on `EADDRINUSE`), passes the fd to `TCPStore`, and publishes the real port through a `/tmp/vllm_dist_port_<port>` file the other ranks poll; `env://`, multi-node and explicit-store calls pass through. `pin_memory_patch.py` forces vLLM's cached pooling `PIN_MEMORY` constant off. `accelerator_empty_cache_patch.py` wraps `torch.accelerator.empty_cache` so the "is not a DeviceAllocator" error at engine shutdown does not leak Neuron cores. Import-time on purpose: the EngineCore subprocess never calls `check_and_update_config`.
6. **Worker-init patches** (`NeuronWorker.init_device`, in order): `apply_shm_reader_spin_patch` (`SpinCondition.wait` busy-loop default; idempotent, also applied by the engine-core wrapper of mechanism 3); `apply_replica_mesh_patches` (`replica_mesh_patch.py`: re-wraps `dist.new_group` through Lite's mesh registry and swaps vLLM's module-global `init_model_parallel_group` and `init_world_group` for the Neuron factories, `_patch_vllm_init_model_parallel_group` and `_patch_vllm_init_world_group` in `neuron_parallel_state.py`, so every group declares its full partition; the XLA compile needs byte-identical HLO per rank, and the patch is installed on both routes before any group exists); then `_init_neuron_distributed_environment_and_runtime` → `init_neuron_distributed_environment`, where `_patch_destroy` wraps `destroy_model_parallel` (original saved and restored at teardown, the only reversible patch), `_patch_getters` adds the `get_neuron_*` accessors, and `in_the_same_node_as` is replaced at two sites (`neuron_worker.py` production path, `neuron_parallel_state.py` test path) because the upstream version calls `torch.distributed.barrier()` and crashes on the PrivateUse1 backend.
7. **Scheduler-time patch.** `apply_jf_grammar_rollback_patch` (`jf_grammar_patch.py`) is applied from `NeuronScheduler.__init__` to one `StructuredOutputManager`: it rolls the xgrammar matcher back after a jump-forward NEFF so jump-forward tokens are not accepted twice. Marker `_jf_rollback_patched` on the manager.
8. **Encoder-prefill-decode shm patch.** `apply_epd_shm_patch` (`epd_shm_patch.py`) wraps the upstream encoder-cache wire decoder: an `EPDSHM1:` descriptor attaches the named reader store, any other string falls through to the original base64 decode. Inert for non-shm payloads.

`pyproject.toml`'s coverage omit still lists the wrong path `vllm_neuron/patches/*`; the patches live under `vllm_neuron/vllm/patches/`.

## How patches layer

Order in a full server start:

1. **Import of `vllm_neuron`** in every process: env defaults and kernel-flag seeds, `_init_backend()` (route fork), port-hold, pin-memory, accelerator-empty-cache.
2. **General plugins** in every process vLLM spawns: `apply_patches()` → DP load-balancer.
3. **Registration**: DCP patch (or its audit hook), optimization-level patch, the `use_v2_model_runner` property and the engine-core entry-point wrapper; `NeuronPlatform` installed.
4. **Config build** in the process that constructs `VllmConfig` (never the EngineCore subprocess): `pre_register_and_update`, defaults, then `check_and_update_config` with the timeout patches, the EPD shm patch, and slot injection.
5. **Worker init**: `use_v2_model_runner` re-applied, shm reader spin, replica mesh and group factories, `in_the_same_node_as` replacement, `_patch_getters`, `_patch_destroy`.
6. **Scheduler construction**: the jump-forward grammar rollback.

Precedence: rebinding is last-writer-wins and nothing defends a binding after application; each patch guards only against applying itself twice. Slot injection yields to explicit user config. Wrapper patches (DCP, optimization level, `_patch_destroy`, port-hold, empty-cache, EPD shm) call the saved original; replacement patches (`shutdown`, `_ensure_worker_termination`, `in_the_same_node_as`, the group factories) discard it. Only `_patch_destroy` can be undone.

## Lessons from the 0.24 line and Neuron SDK 2.32

Measured on a port campaign at `release-0.24.0.1.1.0`, re-checked at that pin. Match the construct, not the line.

**Upstream decides at a consumer you did not patch.** Upstream branches on spec-class identity, on data-parallel degree above one, on a CUDA-alike platform test, and on per-architecture config hooks that rewrite fields before the platform gate reads them. So a feature that looks armed can be inert, a unification path can reject the port on class identity before reading a width, and admitting a name into the platform gate is not inert upstream. Duty: trace the resolver AND every downstream consumer's own gate before rating a feature armed or a config name inert, and prove inertness with a completed compile, never a read-audit. Measured: a config hook rewrote the checkpoint quantization method in place, so the platform allowlist and the plugin's quantization literal both had to admit the rewritten name. Also: `max_model_len` above the shipped single-shot-prefill constant makes segmented prefill mandatory; confirm the model family has that code path before compiling. (L-029, L-314, L-317, L-377, L-378, L-380, L-381, L-382)

**Import time pins the venue before your code runs (measured on the XLA route).** Importing the fork runs unconditional environment and torch mutations before the XLA runtime initializes: XLA functionalization off, a fast-math flag on, an always-all-reduce flag forced, the XLA device pinned to CPU; platform constants such as the fp8 clamp maximum freeze at first import; lazy operator overrides register once, two disabled without an explicit pattern; the top-k override patches torch globally and emits its custom call only for the largest-sorted-last-dimension case; a fused-softmax override needs its own env flag; the worker deletes any environment key absent from its inherited baseline. The native route has its own import-time pins (the kernel-flag seeds, the Lite device registration); the duty is the same. Duty: a probe that claims production tracing or lowering compatibility matches the runner's import order, construction context, parallel degree, dtype, and compile route, sets import-read overrides before import, and confirms package paths with `__file__`. A smaller probe states which property it tests and which production behavior stays untested; a CPU reference cannot validate a device-only fp8 matmul. (L-122, L-145, L-187, L-285, L-299, L-320, L-331, L-333, L-341, L-371, L-373, L-388, L-389)

## Porter rules

1. **Choose the layer by process scope.** Active in every process vLLM spawns (API, EngineCore, workers): the general-plugin layer (pattern: `dp_load_balancer_patch.py` from `apply_patches()`) or import time of `vllm_neuron` (pattern: `port_hold_patch.py` from `__init__.py`; use it when the patch must run before vLLM's plugin loader does). Shapes engine configuration only: `NeuronPlatform.check_and_update_config`. Needs an initialized distributed runtime: the `NeuronWorker.init_device` chain. Needs the structured-output manager: `NeuronScheduler.__init__`.
2. **Prefer sanctioned slots over rebinding.** `worker_cls`, `scheduler_cls`, `kv_connector` plus `kv_connector_module_path`, `get_attn_backend_cls`, `ModelRegistry.register_model`; subclass upstream classes (pattern: the NIXL connectors) instead of patching methods.
3. **Choose the route scope.** Test the route with `envs.is_native_backend()`, never by reading `VLLM_NEURON_BACKEND` yourself (it has aliases). A patch beside the XLA branch of `_init_backend()` or inside a `torch_xla` import never runs on the default route; an XLA-only addition is deprecated with the route and says so.
4. **Rebind every binding.** Upstream `from X import y` makes copies that keep the old function (proof: the dual `shutdown` rebinding). Grep upstream for `from <module> import <symbol>` before patching `<module>.<symbol>`.
5. **Make every patch idempotent.** A module global or a marker attribute on the replacement; spawn re-imports and repeated hook calls happen.
6. **Wrap, do not replace,** when upstream behavior must survive a version bump: save and call the original.
7. **Know what breaks a patch at a bump:** a moved module path or renamed symbol (apply-time `ImportError`/`AttributeError`); a new upstream import binding (rule 4); a class patch that does not survive a spawn (pattern: `use_v2_model_runner`, re-applied in the worker); circular-import timing at registration (the DCP and `use_v2_model_runner` patches have an audit-hook fallback; copy it if yours must run then).
8. **Respect env gating and user overrides.** The timeout patches are inert at the default; slot injection yields to explicit config; the optimization-level patch yields to a passed value. Check a patch's guard before assuming it is active.
9. **Torch patches are not vLLM patches.** `init_process_group`, the pooling pin-memory constant, `torch.accelerator.empty_cache`, and on the XLA route `torch.neuron` and `torch.accelerator.current_accelerator` patch torch at import time; torch-adjacent changes land there, not in `NeuronPlatform`.
